# Hardware for the RNS-E

KiCad designs of boards that go with the software for the Audi RNS-E
(the rnse emulator and the kit and programs built on it). Each board is
a directory of its own, with its README:

| Board | What it is | State |
|---|---|---|
| [`nes-can`](nes-can/README.md) | two original NES controllers on the infotainment CAN bus, for the NES port; ATtiny1616 firmware in `nes-can/firmware` | revision A, not built |
| [`ps2-can`](ps2-can/README.md) | a PS/2 keyboard and mouse on the CAN bus | revision A, not fabricated or electrically tested; no firmware yet |
| [`sdbridge-card`](sdbridge-card/README.md) | the SD bridge (an RP2040 that answers as an SD card) on a board the outline of a full-size SD card, powered by the slot | PCB rev B; CAD and electrical checks done, not yet qualified in a unit |

Paths in this directory's files are written from its own root
(`hardware/` in the rnse repository).

## Fabrication files

Gerbers, drill files, BOMs and placement files are committed as
generated by each board's scripts. The ZIP archives a fabricator wants
are not: each board's script makes them (`sh sdbridge-card/fab.sh`,
`python3 nes-can/package.py`).

## Using them

These are prototypes. ERC and DRC results describe checks of the CAD
data, not a built board, and none of them is qualified for a vehicle.
Wiring anything into a car's electrical system or a unit's CAN bus is at
your own risk, as are your unit, your discs and your data. Software run
on a unit with one of these boards has to keep the display's fold-down
and the disc's eject working at all times (see `CLAUDE.md` in the
repository that builds it).
